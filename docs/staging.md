# Offline ingress checks

Verify three independent facts before admitting a worker: **where** the artifacts came from, **which bytes** are staged, and **what** the runtime can actually load. A local file hash does not establish registry ownership, and a successful registry login does not establish the contents or platform of an image.

`verify_image_pair` in `joey_research.staging` takes the raw base and worker manifests and their configuration blobs, read **by digest** from the approved mirror. It checks the [publisher base lock](../locks/worker-base.json), the independently pinned worker digest, Linux/amd64, and the entire ordered base prefix of both compressed and uncompressed layer descriptors. It rejects external-layer URLs and image indexes in place of the selected platform manifest. Registry authorization and a real pull remain separate checks.

`verify_payload(root, receipt_bytes, receipt_sha256=..., discovery_sha256=..., wheel_lock_bytes=..., wheel_lock_sha256=...)` checks a materialized, read-only directory, not a remote URL. Obtain the pins independently of this directory. The `joey-discovery-bundle/v1` receipt contains an `assets` array: `path`, `bytes`, `sha256`, `source`, `revision`, `license`. Include the exact stock model and tokenizer files, the eight approved patched runtime files, upstream notices, a pinned wheelhouse and the label-free discovery shard. The verifier hashes every listed file, rejects extra or missing wheel entries, checks the shard schema, and refuses links, unknown collections, floating revisions and a bundle larger than 40 GiB.

The [candidate wheel inventory](../locks/linux-inference-candidates.json) pins 40 public artifacts for the publisher's reference stack, including the optional CUDA kernel. Its file digests come from release metadata; no package installation or GPU ABI compatibility is implied. Check the actual mirrored base's Python, torch C++ ABI, CUDA and system libraries before approving the build. Retain the third-party notices from the actual staged packages.

These functions do not import from a public registry, install packages, execute model code, validate license grants, or authorize Kubernetes jobs. An independent offline import/parity check is still required for the wheel closure and approved runtime. Never point a GPU workload at an upstream service to get past an incomplete mirror.

`workload.compile_discovery` renders exactly one immutable packet ConfigMap and one one-GPU Job for an unexpired scheduler ticket. It never sends either to Kubernetes. It binds a verified namespace, distinct pool hosts, an immutable private image, and run-exclusive durable results. A shared `default` namespace requires explicit owner selection: pin its UID and independently match the selection digest at admission. Own and label the individual run objects, not the namespace. Never modify the namespace, shared service account or other workloads. A controller must also verify result-storage identity, fixed pool capacity, admission side effects, pull access and packet/manifest identities before any create.

The container has no credentials for Kubernetes, no host mounts or public service, no retries or priority preemption, and no raw research output in its logs. It writes to a unique token directory on the authorized result volume; the coordinator must verify completion and copy/verify results in private storage. A parity-gated simulation is not a measured run.
